# 🏋️ PoseNutri - Detailed Project Structure & Documentation

This document provides a comprehensive overview of the **PoseNutri** project, an AI-powered gym trainer platform. It explains the purpose of the overall project, its architecture, and provides a highly detailed breakdown of each directory and the precise logic contained within each significant file.

## 🌟 Project Overview

**PoseNutri** is an advanced fitness and nutrition tracking platform that leverages Artificial Intelligence to provide real-time pose estimation, food recognition, and personalized fitness/diet plans. 

The application is built using a modern **microservices-inspired Monorepo** architecture consisting of three main components:
1. **Client (Frontend):** A dynamic, responsive React application built with Vite and Tailwind CSS.
2. **Server (Backend API):** A robust Node.js and Express application connected to a MongoDB database (MERN stack).
3. **AI Service (ML Microservice):** A Python FastAPI service that handles heavy machine learning tasks like YOLO-based food recognition and MediaPipe-based pose estimation.

## 📁 Directory Structure Breakdown In Detail

### 1. `client/` (Frontend Application)
The `client` directory houses the user interface. It is built using **React (Vite)** for fast compilation and **Tailwind CSS** for styling. State management is handled by **Zustand**, and routing is managed by **React Router**.

#### Configuration Files:
*   **`package.json`**: Lists dependencies like `react`, `framer-motion` for complex animations, `axios` for HTTP requests, `zustand` for state management, `@mediapipe/pose` and `@mediapipe/camera_utils` for webcam tracking, and `recharts` for data visualization.
*   **`vite.config.js`**: Configuration for the Vite bundler.
*   **`tailwind.config.js`**: Contains the custom design system rules, including specific colors (e.g., Slate, Blue, Orange accents) and custom fonts (Oswald, Poppins) used throughout the app.

#### `src/` Directory:
*   **`App.jsx` & `main.jsx`**: The root of the React application. Sets up `react-router-dom` routing and global context.
*   **`index.css`**: Global stylesheet containing Tailwind directives, custom CSS variables, and the `glassmorphism` surface styles used for UI panels.
*   **`store/useAuthStore.js` (implied)**: A Zustand store that holds the global authentication state (JWT token, user data) and functions to login/logout.

#### `src/components/` (Reusable UI):
*   **`Navbar.jsx` & `Sidebar.jsx`**: The main navigation structures for the application. They respond to authentication state.
*   **`NutritionScanner/UploadZone.jsx` & `ScanResult.jsx`**: Components used in the scanner page to handle drag-and-drop file uploading and rendering the AI response (bounding boxes on images).
*   **`MiniCart.jsx`**: A slide-out shopping cart component for the e-commerce functionality.

#### `src/pages/` (Main Views):
*   **`Home.jsx`**: The landing page introducing the application.
*   **`Dashboard.jsx`**: The main hub for a logged-in user, likely displaying charts (using Recharts/Chart.js) of their workout history and nutrition logs.
*   **`NutritionScanner.jsx`**: A sophisticated page that lets users upload an image of their food. It sends the image as a `multipart/form-data` to the backend API (`/api/nutrition/analyze`) and renders a loading overlay ("Running YOLOv8 Detection") until the response returns the detected foods and USDA nutritional totals.
*   **`TrackWorkout.jsx` / `WorkoutTracker.jsx`**: Interfaces for logging manual workouts or using webcam-based pose tracking.
*   **`AIPlans.jsx`**: Displays custom workout and diet plans generated by the AI based on user parameters (weight, goal, timeframe).
*   **`Login.jsx` & `Register.jsx`**: Forms for user authentication.

### 2. `server/` (Backend Node.js API)
The `server` directory contains the main business logic, database interactions, and authentication systems. It uses **Node.js, Express.js**, and **Mongoose** (MongoDB).

#### Configuration Files:
*   **`package.json`**: Lists backend dependencies: `express`, `mongoose`, `bcryptjs` (password hashing), `jsonwebtoken` (auth), `multer` (file uploads), and `@google/genai` (for Gemini 2.5 Flash).
*   **`src/index.js`**: The main server entry point. Connects to MongoDB, configures `cors`, `express.json()`, and mounts all the routers.
*   **`src/seeder.js`**: A script to wipe and populate the database with dummy data for development.

#### `src/models/` (Mongoose Schemas):
*   **`User.js`**: Stores user credentials (hashed password), profile data, and fitness goals.
*   **`WorkoutLog.js` / `Workout.js`**: Schema for saving workout sessions (title, duration, calories burned, list of exercises, date).
*   **`NutritionLog.js` / `NutritionScan.js`**: Schema for saving logged meals and their nutritional breakdown (calories, protein, carbs, fats).
*   **`Product.js`, `Order.js`, `Cart.js`**: Schemas for managing the e-commerce store (fitness gear, supplements).

#### `src/controllers/` (Business Logic):
*   **`aiController.js`**: Contains the `generatePlan` function. It takes user parameters (weight, goal, dietary preference) and sends a highly specific prompt to **Google's Gemini-2.5-Flash** AI to generate a strictly formatted JSON response containing a 7-day workout plan and a 5-meal diet plan.
*   **`workout.controller.js`**: Contains CRUD functions like `createWorkout` (saves a new workout to the DB), `getWorkouts`, and `getRecentWorkouts` (fetches the last 5 workouts for the logged-in user).
*   **`nutrition.controller.js`**: Handles saving nutrition logs. It also likely proxies the image upload to the Python AI service for YOLO detection.
*   **`auth.controller.js`**: Handles user registration (hashes passwords with bcrypt), login (compares hashes), and issues JSON Web Tokens (JWT).

#### `src/routes/` (API Endpoints):
*   These files (e.g., `aiRoutes.js`, `workout.routes.js`, `auth.routes.js`) simply map HTTP methods (GET, POST) and URL paths to the specific functions in the controllers. They also apply middleware, like verifying the JWT before allowing access to private routes.

### 3. `ai_service/` (Python ML Microservice)
This is a dedicated API for processing heavy Machine Learning tasks. It is built using **Python and FastAPI**.

#### Configuration Files:
*   **`requirements.txt`**: Specifies packages like `fastapi`, `uvicorn` (ASGI server), `ultralytics` (for YOLOv8), `mediapipe` (for pose estimation), and `python-dotenv`.

#### Key Source Files:
*   **`main.py`**: Initializes the FastAPI app, configures CORS, and includes the routers for `/pose`, `/food`, and `/plan`.
*   **`models/food_yolov8n.pt`**: A pre-trained PyTorch weights file for YOLOv8 (nano). This model has been specifically trained to recognize various food classes (e.g., 256 classes) to power the Nutrition Scanner.

#### `routers/` (FastAPI Endpoints):
*   **`food.py`**: Receives an image from the Node backend or React client. It loads the `food_yolov8n.pt` YOLO model, runs inference on the image to detect food items, and draws bounding boxes around them. It likely returns the list of detected foods and the annotated image back to the caller.
*   **`pose.py`**: Uses Google's MediaPipe framework to analyze video frames or images of a person. It calculates body joint coordinates (shoulders, elbows, hips) to track exercise form, count repetitions, and ensure proper posture.
*   **`plan.py`**: Similar logic to the Node server's AI controller, but written in Python. It might serve as an alternative endpoint for generating fitness plans using a different LLM or logic.

## 🛠️ How Data Flows Between Files (Example: Nutrition Scan)

1. **User Action:** The user uploads a photo on the React page (`client/src/pages/NutritionScanner.jsx`).
2. **Client Request:** The React app uses Axios to send a `multipart/form-data` POST request to `/api/nutrition/analyze` on the Node server.
3. **Server Handling:** The Node Express server receives it via `server/src/routes/nutrition.routes.js`, which passes it to `server/src/controllers/nutrition.controller.js`.
4. **AI Processing:** The Node controller forwards the image to the Python FastAPI microservice at `http://localhost:8000/food/...`.
5. **YOLO Detection:** `ai_service/routers/food.py` processes the image using `models/food_yolov8n.pt`, finds the food, and returns the classes.
6. **USDA Lookup & Response:** The Node server takes those food names, potentially looks up their macros (e.g., via USDA database), and returns the final JSON to the React client.
7. **UI Update:** The React state updates, and `ScanResult.jsx` displays the nutritional breakdown and the annotated image to the user.
